System Architecture

システム構成図

登場するのは5つだけ。矢印は実際のデータの流れ。矢印上の①〜⑤は、1回の投稿処理（daily.yml）が実際に進む順番。

🔑 GitHub Secrets ⏰ 2つのワークフロー 🤖 GitHub Actions Runner ✨💬 2つの外部API 📒 Gitリポジトリ
コンポーネント役割技術・詳細
🔑 GitHub Secrets 認証情報の保管 コードには一切書かず、実行時だけRunnerへ渡す。THREADS_ACCESS_TOKEN / THREADS_USER_ID / GEMINI_API_KEY の3つ。
⏰ daily.yml 日次実行のトリガー cron ×6（07:00/12:00/18:00/21:00/23:00/01:00 JST）+ workflow_dispatch（手動実行）。同時実行を防ぐ concurrency 設定つき。
🗓️ weekly.yml 週次実行のトリガー cron ×1（月曜03:00 JST）+ workflow_dispatch。aggregate.py → review.py の順に実行。
🤖 GitHub Actions Runner スクリプトの実行環境 毎回払い出される使い捨てVM（Python 3.12）。起動時に checkout、終了時に commit & push して消える。このほか build_seeds.py / build_ephem.py を企画開始前に1回だけ手動実行し、seeds.jsonl / ephemeris.jsonl を作る。
✨ Gemini API 投稿文の生成・重複チェック用の埋め込み post.py（本文生成・埋め込み計算）と review.py（方針の書き換え案の生成）から呼び出される。
💬 Threads API 投稿の公開・実績の取得 下書き作成 → creation_id で公開する2段階方式。collect.py が views/likes/followers_count 等を取得。
📒 Gitリポジトリ 唯一の永続化層 DBもサーバーも使わず、JSONL/Markdownのファイル群だけで状態を管理。全履歴が git のコミットログとして残る。
📦 requirements.txt 依存パッケージの一覧 requests / google-genai / skyfield の3つだけ。Runner起動時に pip install -r requirements.txt で読み込む。
📖 README.md / .gitignore リポジトリの説明・Git管理対象外の指定 実行中に書き換わることはない静的なファイル。.gitignore は skyfield が使う天体暦データ(de421.bsp)などをコミット対象から除外する。
Foundations

土台となる3つの約束事

サーバーもデータベースも使わない代わりに、この3つのルールで全体を縛っている。

🖥️ 実行基盤はGitHub Actionsだけ

サーバーもDBも借りない。データの保存先も同じGitリポジトリの中のファイルで、実行のたびにスクリプト自身が commit & push する。

🛡️ キャラの中身は誰にも壊させない

「口調は崩す。内容は崩さない」など6つの絶対ルールを明文化。週に1回AIが方針を書き換える時も、このルールだけは機械的にチェックして守らせる。

🧮 数字の集計にAIを使わない

どのパターンの反応が良かったかはプログラムが淡々と計算する。AIに数字を作らせず、AIには「正しい集計結果」だけを渡して判断させる。

Q. 投稿ってどこに残るの？

投稿ログ（data/posts.jsonl）も、方針（strategy.md）も、使った語彙（gyaru_lexicon.md）も、 全部このGitHubリポジトリの中の“ただのファイル”。

作業ロボットは動くたびにノートをまっさらな状態から開き、投稿が終わると ロボット自身がその内容をノートに書き足して閉じる。 人間の代わりにAIが自分でつける日記のようなもので、データベースを一切使わなくても履歴がそのままGitHub上に積み上がっていく。

Per-Post Pipeline

投稿1回のしくみ

ロボットが起きるたびに、この8手順を順番にこなす。

01 🔍

投稿もれチェック

予定より投稿が遅れていないかを見て、遅れていれば最大2本まとめて投稿する。

02 🎴

お題を1つ選ぶ

「恋の局面×気持ち×シーン」420通りのうち、まだ使っていないものを1つ取る。

03 🌙

星まわりを見る

新月・満月・水星逆行など、その日の天体の出来事を調べる。何もない日はそのまま進む。

04 🎯

今日の書き方を決める

星座に触れる/触れない × ギャル口調/標準口調、4パターンを順番に割り当てる。

05 ✨ Gemini API

本文を生成

今週の方針・使う言葉・お題・星まわりを渡し、Gemini APIに1投稿ぶんの文章を書かせる。

06 🔁 Gemini API

似た投稿と比較

過去の投稿と埋め込みベクトルの近さを計算。似すぎていれば書き直し、3回失敗したら別のお題に切り替える。

07 📤

Threadsへ投稿

下書きを作ってから公開する、という2段階で実際に投稿する。

08 💾

記録して保存

使ったお題・投稿文を記録ノートに書き足し、ロボット自身が保存する。

Weekly Cycle

週に1回、AIが自分の方針を見直す

月曜の朝、その週の結果を踏まえて「今週の方針」そのものを書き換える。

01 📊

1週間分を集計

プログラムが淡々と、パターン別の閲覧数・反応率などを表にまとめる。

→
02 🧠 Gemini API

来週の方針を提案

集計結果だけをGemini APIに渡し、勝ち負けの判断と次に試す案をJSONで出させる。

→
03 🛡️

絶対ルールを検証

絶対に変えてはいけないルールが書き換えられていないかを機械的にチェック。もし破られていたら、そこで止めてエラーにする。

→
04 ✏️

方針を更新

今週の方針と、使ってはいけない言葉リストを書き換え、変更した理由を履歴に残す。

この4手順を、契約期間中は毎週月曜に繰り返す
